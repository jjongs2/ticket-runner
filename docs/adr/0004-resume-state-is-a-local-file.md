# Resume state is a local file, not a tracker comment

Where a released Ticket resumes from is written to a gitignored file under `.agent-pipeline/state/`, not to a comment or a label on the issue. The issue is the shared board and everything written there is addressed to a human; a machine-readable resume record posted as a comment would be noise a human has to scroll past and, worse, a second source of truth beside the labels the triage state machine already owns. The State file sits beside the branch and worktree it is about, all three are local, and all three are only meaningful on the machine that has them — a Ticket released on one checkout cannot be resumed from another, which is the cost we accept. It also means `.agent-pipeline/` is only safe to delete when nothing is resumable (CONTRIBUTING.md says so), and that a State file whose worktree has been deleted is ignored rather than trusted: the Ticket is taken from the top instead. That can itself fail at setup, because the branch may still be there, and the Ticket is then handed over with the failure naming it — which is the right outcome, since silently reusing a branch nobody can account for is worse than asking.

We also rejected making this a fourth port beside `Tracker`, `AgentRunner` and `Workspace`. The three ports exist to isolate the effects the pipeline has on the world outside it — GitHub, Claude, git — and a JSON file in the pipeline's own gitignored run directory is not one of those; it is the same kind of local bookkeeping as the Run lock and the Stage transcripts, neither of which is a port either. Whether the branch and worktree the file names are still there *is* the world's business, so that question goes through `Workspace.hasWorktree`. The cost is that the orchestrator tests which reach the release and resume paths run against a temporary repo root rather than purely in memory, which also means those tests assert the file a later Run would actually read.
