# Resume state is a local file, not a tracker comment

Where a released Ticket resumes from is written to a gitignored file under `.agent-pipeline/state/`, not to a comment or a label on the issue. The issue is the shared board and everything written there is addressed to a human; a machine-readable resume record posted as a comment would be noise a human has to scroll past and, worse, a second source of truth beside the labels the triage state machine already owns. The state file sits beside the branch and worktree it is about, all three are local, and all three are only meaningful on the machine that has them — a Ticket released on one checkout cannot be resumed from another, which is the cost we accept. It also means `.agent-pipeline/` is only safe to delete when nothing is resumable (CONTRIBUTING.md says so), and that a state file whose worktree has been deleted is ignored rather than trusted: the Ticket starts over, which is always safe.
